# 乐芙兰确认费用、映像创建与内嵌复制重审

本批重写乐芙兰征服/据守创建映像的时序，复用上一批的指示物替换与创建基础设施。其他传奇费用、全部目的地选择及所有复制交互不据此标记完成。

## 权威与正确时序

依据中国区官方核心规则、裁判 QA、乐芙兰勘误及官方卡牌目录，见 [authority.json](evidence/leblanc-creation-2026-10-09/authority.json)。本批复查本地官方文件哈希，未重新同步全站。

**204.3.a 必须和 204.3.b 区分：触发效果开头的“弃置并休眠，以此……”属于确认该触发所需的基础费用。** 乐芙兰必须先由玩家选择弃牌并横置，才能确认外层技能、开放第一次响应。法术或触发后半部分的指示费用才在结算时支付。本轮初始实现曾错误沿用后者，已在提交前按条文修正并重跑验证。

最终流程：

1. 征服或据守捕获来源身份、对象代次及精确战场。选择一张合法手牌支付弃牌及横置费用，或明确放弃；不再自动选择第一张手牌。
2. 完成费用确认后双方可以响应。费用收据留在父结算项目上，恢复和后续结算不再次支付。
3. 外层技能结算时才选择基兰替换，并通过共用工厂在捕获的战场创建活跃、0 战力映像；新增映像继承相同入场调整。
4. 创建完成后，内嵌复制技能单独确认目标。仅能选择该战场另一个合法单位，原映像和本次追加的映像均不能成为它自己的复制来源。必要的法盾费用共用触发目标确认支付路径。
5. 双方再次响应后，复制仍合法且对象代次匹配的单位；来源返回手牌、重入或离开指定战场时不能继续复制旧对象。映像保留已有眩晕及移动限制，已确认技能的后续瞬息照常处理。

内嵌触发确认时完全没有合法目标则依 355.8 从结算链移除，不擅自改选基地、其他战场或某个自动目标；已经创建的映像不会因此被撤回。落岩之径的禁止打出优先于创建许可，既不生成映像，也不消耗基兰的替换次数。

## 共用实现与清理

- 删除立即创建/自动弃牌的 `TryResolveLeblancLegendImageTrigger` 及其旧来源查找函数，移除 `LEBLANC_COPY` 中间步骤和旧 `SelectedCostObjectId` 字段。征服与据守进入同一费用确认与创建流程。
- `DiscardExhaustCostReceipt` 保存已付费用的对象绑定；手牌合法候选仅给付款者，错误玩家、过期选择、伪造收据及绕过确认均被拒绝。
- `CoreRuleEngine.UnitTokenEntry.cs` 提供共享批量创建、工厂身份、静态入场调整、精确位置及逐单位进场事件。上一批三种传奇召唤和本批映像共用该实现。
- 内嵌复制沿用同一 `ReflexiveCopyContext`，增加战场范围及确认状态；目标、对象代次和收据参与序列化、恢复与动作回放。
- 各类费用/目标确认由统一入口按照结算链项目加入顺序调度，取消按规则家族固定优先的选择方式。两种混合排序均验证在所有必要确认结束前不开放优先行动权。
- 原生客户端显示“确认映像费用”、弃牌及横置后先响应的摘要，以及“映像创建”/“内嵌复制”结算链标签；费用、替换、复制分别是后端控制的明确阶段。

## 验证

新增 19 个案例。最终 `check` 9044/9044 通过，测试 76.56 秒、含构建与发现共 82.16 秒；相关完整对局 2/2 通过并验证获胜及动作回放。Godot 构建零警告零错误，原生三条命令进入两条后端分支后恢复/回放一致。上一批 94bf2af2 的 CI 已完整成功；本批全量规则、连接恢复和双平台打包由推送后的 CI 单独验证。

最终计数、命令和证据见 [validation.json](evidence/leblanc-creation-2026-10-09/validation.json)。覆盖普通/多来源替换、官方两段基兰 QA、两个响应窗口、据守后正常回合流程、敌方法盾、精确战场范围、禁止打出、错误玩家/旧选择/恢复伪造、薇古丝逐个触发及复制后状态保留。

测试中新增场景曾漏填战场物体自身的精确位置，使后端正确拒绝基兰替换；已修正场景，没有放宽位置校验。历史测试中立即弃牌/创建及虚构战场的正例改为真实征服、明确费用确认和独立复制，保留权限、属性、事件与目标限制断言。

原生证明使用真实服务器 prompt 和生产按钮：选择第二张手牌 H2 支付、空选择放弃，以及映像入场后的合法复制对象确认。唯一合法复制目标由生产控件预选，但仍通过真实确认按钮提交。三条原生命令必须再次送入 MatchSession，并核对序列化恢复及动作/事件回放；仅导出 prompt 不算通过。

## 后续范围

- 维克托/莉莉娅的基地或受控战场选择，以及其他“在此处”指示物来源仍需迁入统一的位置选择流程。本批只落实乐芙兰固定战场的精确创建。
- 其他据守/征服触发开头的可选弃牌、横置、摧毁费用仍需逐项按 204.3.a 重审，不能假设原 `HOLD_EFFECT` 的结算中选择均正确。
- 战场替换后的地点引用、更多不同类型替换的混合顺序、任意复制层与同名指示物不同版本选择仍未全部验证。
- 用户当前服务/对局未重启。原生验证是 headless 生产控件与后端回放，不等同于人工视觉、新双客户端完整实战或 Windows 实机验收。
