# 原生双人对战平台：2026-10-04 实施记录

## 目标和权威

用户确认正式双人对战采用中国区官方规则与禁限牌。交付路线为 Godot .NET 原生客户端（macOS / Windows）+ .NET 权威服务端。React DevUi 保留为调试与协议回归工具。

中国区来源：https://www.playloltcg.com/rules.html 和 https://www.playloltcg.com/card.html 。本次抓取卡牌 1,374 条，较旧快照净增加 365 条（新增 369、移除 4），下载 13 份官方规则、FAQ、勘误和禁卡文档。来源 URL、更新日期及 PDF SHA-256 见 `data/official/upstream/2026-10-04/rules-manifest.json`。国际服禁卡表不混入。

## 已实现

- 连接存在性由服务端维护：离线玩家不再被匹配，房主离线时公开房间隐藏，只有重新进入该房间后恢复显示；另一窗口仍在线时不会被误删。
- 同一连接不能切换认证身份；客户端身份变化时重新连接。
- 正式 API 的卡组提交与准备阶段校验 `CN-STANDARD-2026-07-24`。预组目录过滤禁卡。相同牌名的异画版本同样禁用，德莱文只匹配「血斧飞旋」。2v2 特有的易传奇禁用不适用于双人标准对战。
- 历史引擎 fixture 保留 `CoreRules` 构筑校验；服务端固定使用中国区标准赛制，客户端无法选择绕过禁卡。开局准备重新校验已有卡组，防止旧等待房间绕过校验；进行中的历史对局不被追溯改判。
- Godot 4.7.2 项目、解决方案和双平台导出预设；卡牌资料打入 PCK，使用资源 API 读取，移除对源码目录的运行时依赖。
- 原生大厅增加服务器地址、随机初始身份和房间号、英雄卡图预览、公开房间刷新与新的配色。预组说明改为面向玩家的玩法描述。
- 桌面快照即时渲染；卡图最多 6 路后台下载、缓存、合并刷新，网络超时不阻塞桌面；缓存写入原子化以支持两个客户端共享缓存。结果后仍保留桌面快照。
- 修复 DevUi 组卡主按钮文字不可见，以及 E2E 假设固定先手导致换牌流程不稳定的问题。

## 本批基础规则与可用性修正

- 普通单位按中国区 143.4 休眠入场；战场目的地必须是自己控制的实际战场，阻止使用旧 P1-MAIN 字符串绕过校验。明确的备战入场文本及已支付急速费用保留。
- 480 个历史 JSON fixture 仅迁移普通单位入场后的休眠预期，并添加具体官方依据；不是删除失败或仅修改计数。迁移前逐项执行并比对失败字段。
- 争夺使用单位的实际控制者；空战场不回退到所属者。同回合新争夺不受旧法术对决完成标记阻塞。
- 资源反应可以在对决/闭环窗口按焦点或优先权使用，不能越过对手行动权；横置或回收符文不会推进结算链。
- 遗忘丰碑只限制其自身战场的得分，第三回合后恢复正常据守；荣耀竞技场同样保留普通据守计分。
- 休眠不会让单位退出战斗候选；标准移动后仍能进入战斗。同一实际战场上的所有双方单位由服务端加入战斗；不再限制每方两名。进攻方取实际引起争夺的玩家。战斗自动启动、伤害分配与效果排序仍需继续逐条重审。
- 桌面卡图增加 mipmap 与有界纹理缓存；固定手牌/操作区域，场面纵向滚动；异步卡图可刷新换牌弹窗且保留选择。详情使用中文费用/战力和可换行规则文本；动态按钮统一样式。
- 身份重名失败后主动断开，允许改名重试，避免大厅按钮被连接状态锁死。
- 原生客户端自动网络重连后重新认证、恢复房间并等待新的 Joined/Snapshot 回执；恢复失败保持不可操作。断线桌面显示状态与重试/返回大厅按钮、关闭旧选择并隐藏操作栏。NativeNetworkSmoke 使用实际客户端网络源码和本地 API，经 TCP 连接中断验证恢复；错误重连令牌不能被随后收到的 Snapshot 掩盖成恢复成功。macOS 打包应用还通过本地代理断网/恢复实测，并在恢复后完成两名单位同时移动。
- 标准移动支持多名单位同时移动到同一目的地：后端先验证所有对象与费用，再共同休眠/移动，然后处理触发、清理与争夺。搜魔人巡管按额外移动单位收取任意符能；允许合法游走到真实战场，不以战场 ID 的玩家前缀裁决。
- 自己的待命牌可查看，明确标注“待命 · 牌面仅你可见”；对手与旁观者继续隐藏。原生纯快照解析测试同时覆盖误带牌号的对手背面卡仍被屏蔽、己方待命可识别，以及实时战力/伤害只使用权威快照。
- 原生移动窗口使用服务端候选对象和目的地，支持多选、中文战场名、Escape 取消、prompt/tick 过期自动关闭。法力与符能常驻手牌标题栏。
- 自动伤害与玩家分配伤害共用战斗收尾，包括摧毁后的技能、据守/征服、计分、控制权与后续战场任务；避免两套实现漏触发。保存恢复保留战斗参与者和相关事件的原顺序。
- 寒谷弓手的进攻费用选择移到伤害结算前；支付/放弃后继续伤害分配，来源在之后战斗中死亡也不会吞掉已产生的费用选择。该路径验证不等于所有进攻/防守触发和响应顺序完成。

## 整方战斗伤害分配

- 465.2.a-c.7：同一方的所有来源可共同满足一个目标的致命阈值；同级目标顺序由玩家选择。拒绝同时造成两个不足致命的分配、未完成其他目标时过量分配、跳过壁垒及整数溢出。双方提交前不造成伤害，提交完成后共用战斗清理。
- 原生客户端按敌方目标编辑整方总池，显示卡面、当前战力、已有伤害、致命阈值及优先级。点击卡牌可查看详情并返回；“按优先级分配”使用后端生成并校验的建议；非法提交保留输入并显示后端原因，重新编辑会清除旧提示。
- macOS 安装包实连开发局面 `pooled-combat`：4 点全部给 3 战力壁垒被拒绝，输入保留；服务端建议 3+1 被接受，轮到对手时四名单位仍未受伤；对手提交后四名单位摧毁、战场无控制者。此为指定开发局面验证，不是正式卡组完整对局证明。
- 此次实连另外暴露单位离场后卡牌资料被删除的问题，已由下述区域转换批次修复。

## 未完成，不能标记发布就绪

1. 最新 1,374 条是上游资料快照，运行中的规则卡池仍为原 1,009 条。新增机制包括强化/已强化、流转、燃烧、跳过、多类型等，必须有共享引擎实现、合法选择、支付、事件、隐藏信息、持久化/回放及针对官方条款的测试后才能开放。
2. `core-rule-index.json` 是每个编号条款的重审清单，本次只将 423.1.b/c 两个眩晕条款登记为已对照并验证，其他条款仍需逐条重审。既有 9,000 多项测试证明回归稳定，不自动等于每条最新官方规则已经正确实现。
3. 原卡池也存在未完成的完整可选选择、多目标、触发排序、替代效果等边界。战斗伤害分配已按 465.2.c 汇总整方并支持同优先级自由排序，来源仍作为协议记账维度；伤害替换、相互冲突的优先级和免疫目标选择尚需实现；自动战斗入口和完整进攻/防守触发顺序也未闭合。不能把代表路径通过当成全卡完整验证。
4. Windows 需要在真实 Windows 环境完成启动、缩放、输入、双端联机和长局验证；本机导出成功不等于 Windows 实机通过。
5. macOS 当前为本地 ad-hoc 签名，尚未完成正式发行签名与公证。客户端需要连接可达的后端；本次没有部署公网服务。
6. 整体视觉仍需要更多实际局面（满场、长手牌、多个选择窗口）和不同分辨率验收，不以大厅截图替代完整可用性验收。

## 复现

环境：.NET 10 SDK（原生客户端目标 net8.0）、Godot .NET 4.7.2 及对应导出模板；Node 24 用于 DevUi 协议工具。

```sh
dotnet test tests/Riftbound.ConformanceTests
RIFTBOUND_SERVER_URL=http://127.0.0.1:15089 node src/Riftbound.DevUi/scripts/check-lobby-presence-e2e.mjs
RIFTBOUND_SERVER_URL=http://127.0.0.1:15089 node src/Riftbound.DevUi/scripts/check-matchmaking-result-e2e.mjs
RIFTBOUND_GODOT_BIN=/path/to/Godot clients/godot/tools/export-desktop.sh macOS
RIFTBOUND_GODOT_BIN=/path/to/Godot clients/godot/tools/export-desktop.sh windows
```

Windows 必须分发 `Riftbound.exe` 和旁边的 `data_Riftbound.GodotClient_windows_x86_64` 整个目录。macOS ZIP 内包含完整 `.app`。导出目录在 Git 忽略范围内。
