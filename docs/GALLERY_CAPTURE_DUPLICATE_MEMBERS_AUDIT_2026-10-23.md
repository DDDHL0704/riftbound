# 原始图库 JSON 重复字段拒绝

离线诊断的 `read_capture` 原来直接使用默认 JSON 解析器；同一对象内的重复字段会静默保留最后一个值。本批构造四类完整原响应反例：重复卡牌 `id`、重复 `metadata.locale`、重复顶层 `data` 和重复卡牌 `text`。原读取器均接受，并可让窗口诊断返回 `supportsStableWindowObservation=true`。它虽仍保持缺口未关闭，但“稳定窗口”的依据已经被含糊输入削弱。

修复只在读取入口增加对象成员唯一性检查，普通 JSON 和 gzip 原响应都适用；重复字段值相同、或字段名使用等价 Unicode 转义也拒绝。不同对象各自使用相同字段名仍合法。拒绝发生在报告写入之前，原始文件及其字节保持不变。窗口守恒、排序、身份差额和整行比较算法全部未改，原十项诊断测试文件逐字节保留。

验证先红后绿：新增独立测试文件，六类重复字段分别覆盖普通与 gzip 输入，加上 CLI 的父窗口、子窗口两个拒绝分支，修复前共 14 个子例失败；有效输入对照保持通过。修复后全部 **90 个工具测试方法通过**，CLI 拒绝分支均未生成报告，也未修改输入原件。

从既有 v1/v2 原件归档重新核验全部 285 个成员哈希，再离线读取其中 **129 份 API 捕获及六份历史 HTTP 原响应**。新旧读取结果、全部解析字段和原件哈希完全一致；此前有界窗口 CLI 报告、两组真实历史不守恒报告和八个空单位置均未改变。本次没有在这些实际原件中发现重复字段，没有重新请求官网，也不据合成反例认定官网存在漂移。

本批不改公共 manifest、来源台账、游戏规则、SQL、客户端或测试调度；原 17 个 Drawings 门禁和英文八条差额仍开放。工具测试不替代新固定提交的 full、数据库、原生及业务验收；该读取修复也不代表所有来源输入问题已穷尽。
