# ADR 0003：房间规则配置随权威状态恢复

2026-11-02，已接受。现开规则依据中国区赛事规则 602.1.b、602.4.a.2–6；构筑与现开的禁卡及卡组要求不同，冷恢复和回放必须继续使用建房时的格式。

`MatchState.SessionOptions` 在私有权威状态中保存 `MatchSessionOptions`。新房间使用创建参数；恢复与动作回放使用已记录的配置，进程级缺省值不能覆盖它。默认 CoreRules／允许无卡组准备的历史测试房间以省略该属性表示，保留其原有序列化形式。非默认配置从首个席位日志开始保存，并进入权威状态哈希。PostgreSQL 从最早持久化的权威帧读取配置，校验后续保留帧的配置一致，再重建回放初始状态；不能由最终帧反向覆盖起点配置。

共享 registry 提供 `GetOrCreateAsync(roomId, creationOptions, cancellationToken)`，允许同一进程创建不同规则的房间。`creationOptions` 只用于新房间；已存在或已持久化的房间继续其原配置。原有两参数入口继续使用进程缺省值创建新房间。未实现此能力的 registry 对显式配置调用拒绝，避免丢弃格式参数后创建出错误房间。

权威恢复拒绝未知格式，回放和直接恢复都拒绝初始／最终配置不一致。开发场景重置保留房间配置。玩家快照、行动提示、公开事件和观战回放不序列化内部 `SessionOptions`。

赛事规则 401.5 规定卡组列表通常私密。`HideSubmittedDeckIdentities` 是内部房间配置，供现开房间接入时启用；启用后，共享 `DECK_SUBMITTED` 只记录玩家与各牌堆张数，省略传奇／选定英雄编号。公开事件、API 对象引用投影和观战回放使用同一份不含牌面身份的事件；正式开局后按现有区域规则公开传奇、英雄及所选战场。完整卡组和原始提交命令只保存在私有权威记录中，便于准入与精确动作回放。配置随原始房间持久化，恢复时不接受进程默认值覆盖，也不能中途改写；默认值为 false 且不序列化，保留现有构筑事件和配置的序列化形式。这一设置不控制房间格式或卡池准入。

这是现开任务第三步的通用前置改动，可从 main 独立合入。后续仍需接入建房的 format/setCode/bestOf、私有卡池、种子与卡包记录、重连和现开投影；前端字段继续由现开契约 ADR 定义。本改动不开放新的比赛入口。
