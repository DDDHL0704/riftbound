## 规则与实现

依据 [CN 核心规则](https://cdn.playloltcg.com/lol/2026/10/2026-10-10/a21ead876c6b44d6abe386b6ae54ea28.pdf) 383.2.c.3、429.1.a.1.b、808.1.d.1，真实摧毁提交时记录离场前的印次、控制者、世代、战场和身份；中娅或祭坛召回替换不产生死亡技能。选择对手是技能确认的一部分，之后开放正常响应，结算才得分。

依据 337.1、340.1、383.3.d.1、467.3、468.1–468.7：同一指令中的死亡和后续获胜判定保持先后关系；只在同一时机内应用玩家顺序。确认依入链顺序，结算依后进先出。双方同时阵亡仍先处理技能，随后才处理空战场控制和关闭；某个技能令玩家达到 8 分时，按正常胜利规则结束，不继续下一个技能或战场控制。

共享运行流程已接入死亡捕获、触发队列、对手确认、入链及结算，延续既有战斗结果处理。替换选择暂停原指令时，死亡与战斗结果使用最终接受指令的时间。恢复同时核对上下文形状、原始摧毁事实、触发出生、战斗身份与实际选择；协调篡改当前状态、出生和死亡记录仍须通过完整原日志重演，不能仅靠相互一致的伪造记录。已获得的技能保留原世代，来源回收进主牌堆后，双方投影不暴露其新私有身份。

## 实际验证

- 最终 focus：84 例通过，包含 20 个原死亡场景、16 个原互换场景、33 个新增恢复／反例及 15 个既有获胜恢复场景。另补 4 个同控制者死亡与获胜先后场景，全部通过。
- 原获胜测试完整保留 18 行，新增死亡选择步骤，并分开断言获胜得分和死亡给对手得分；18 例重跑通过，没有删除旧断言或 Theory 行。
- 相邻原轮：314 例，309 通过、5 失败，三个原完整对局通过。四个失败属于上述获胜测试待补的死亡选择，修订后已通过。剩余 `LocalDestructionRecallTests.LethalSpellDamageUsesTheSameRecall` 仍断言 1 点，N54 虚空之门规则产生 2 点；本模块未编辑另一窗口负责的该旧夹具，不将此轮记为全绿。
- 原失败全部保留：中盘初态不满足完整恢复起点；直接构造指令的 null 与网络映射的空数组差异；无结果战斗历史类型；自动入链遗漏指令内先后关系；祭坛拒绝后的出生时间错误。各项归因区分夹具和运行时，没有重写旧接受记录。

新增恢复用例从空房间、真实入座和显式场景指令开始，每个前缀冷恢复并对比双方快照、提示及原始事件。非法对手选择保持权威状态和双方投影不变；重复提交不产生第二条输入。原死亡、互换、获胜和同控制者测试保留其既有 424242 种子及各自原始回放范围。

## 真实网络与 PostgreSQL

独立新建数据库、独立端口与 API 进程，6 个原房间、每房间两名真实认证用户。覆盖来源回收后响应、待选对手、双阵亡、7→8 分终局、祭坛待选择和死亡／获胜交互。实际停止第一 API 进程，启动第二进程后以原用户令牌重连，逐字段核对原快照、提示与恢复帧，再继续原对局。

第二个独立只读程序从真实 7 张表读取原记录，对 83 个原输入前缀全部重新回放。读前读后 7 表原行哈希一致。API 依赖图检查、网络驱动和独立读取程序各自实际加载的四个规则程序集均核对路径、SHA-256、MVID；与通过本地测试的四库一致。两个 API 进程正常退出，独立 PostgreSQL 正常停止，原数据库保留。
