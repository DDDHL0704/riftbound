# 选定英雄与圣化之墓重审（2026-10-09）

## 纠正前提与权威

上一批提出的“真正选定英雄是否只指开局那张实体牌”只是待核查推测，不能作为实现要求。CN **103.2.a.3** 明确：任何与卡组指定英雄同名的英雄单位，都属于选定英雄。**132.4** 又明确名称包括简称和副标，因此“卡莎 - 九死一生”与“卡莎 - 蜕变者”不同名。

本次从[中国区官方核心规则 PDF](https://cdn.playloltcg.com/lol/2026/07/2026-07-23/6f47b6ebe57341a5bb5f4bed5548d051.pdf)重新下载完成，SHA-256 与既有缓存一致：`d0e36d00c954b9802c7f6e2889124a3cc4f2001a2fb6178d6c54f4ec98e25f64`。这确认了引用文件内容，没有宣称已重新同步官网全部资料。

其他直接依据：

- 官方圣化之墓 OGN·281/298：据守时，若英雄区域已无英雄单位牌，可让该英雄从废牌堆返回英雄区域。
- 383.2.a.1：紧随触发条件的附加条件属于触发条件，必须在据守发生时满足。
- 355.5 / 355.10.a / 355.10.d.2：废牌区为公开区域；可能存在多个同名英雄，不能将它当成流程唯一确定的非目标对象。选牌在确认时进行。
- 383.3.e.2：先做可选执行决定，再开放响应。
- 355.15 / 359.3.e：确认后不能换目标；结算时复核目标区域和游戏物体代次。
- 108.3.c.1：英雄区域已有任何卡牌时不能再返回；108.3.d / 419.1.a 允许返回的英雄正常付费打出。
- 124：跨非场地区域产生新游戏物体，使用共享离场重置和代次流程。

## 本批实现

1. `ChosenChampionRules` 按官方英雄单位的完整名称判定，覆盖同名其他实体、异画、重印；排除不同副标和非英雄牌。不新增“开局唯一英雄物体 ID”，不把全部“卡莎”都当成同名牌。目录名称表缓存复用，替代每次候选查询重新构造规则文本身份分组。
2. 圣化之墓在据守发生时检查英雄区条件。满足条件后，复用 `HeldConfirmation` 的先选目标、可放弃、双方响应、代次绑定及结算复核。没有候选时自动结束，不产生空选择或卡住回合。
3. 目标失效时不换选同名其他牌；英雄区被另一个效果占用时不覆盖。多次据守触发先分别确认，先结算的返回成功后，后续返回受区域限制。
4. 删除最后的 `HOLD_EFFECT` 结算中选牌入口、`ResolveHeldChoice`、专用恢复优先权函数，以及 `PendingCardChoiceState.HeldContext` 旧续接字段。历史开发快照不迁移；恢复校验明确拒绝旧窗口。
5. 原生结算链显示“据守返回选定英雄”，候选说明完整名称与返回区域；共用生产确认/放弃控件。
