`data/official/rule-input-scope.json` 冻结 CN/zh-CN、2026-10-14 的已采纳来源。13 份中文核心、FAQ、勘误和赛事资料的文件哈希，12 篇英文补充参考正文以及 1,502 个 QA 身份内容已重新核对；英文资料不能覆盖地区规则。未确认的生效日期保留 null；10 月 16 日生效的中文资料明确排除在本轮活动输入外，原全量 ledger 继续保留。QA 列表顺序变化按精确身份比较，不当作文字变化。这个有限来源集合及运行身份不构成全部官网来源或语义认证。

运行身份由三个实际输入组成：

- `AuthoritySha256`：随程序提供的已采纳来源配置的规范 JSON 哈希，包含 FAQ、QA、勘误及适用范围，不再仅代表主核心 PDF。
- `CatalogSha256`：进程实际共享的不可变默认目录及实际武器定义的规范内容哈希，包含费用、颜色、文本、限制和分类等字段；图片、画师、背景文字及抓取时间不参与。
- `ImplementationSha256`：已加载 Engine、CardCatalog、Contracts 三个规则相关程序集的名称和 MVID。它指向执行中的规则代码；不同构建选项或不同实现可能要求新建开发对局。

`IdentitySha256` 是上述字段与 schema、地区、语言的规范指纹。反序列化必须提供实际字段和记录的指纹，不能把缺失字段补成当前值。默认目录路径和内容在进程内冻结；旧进程继续使用已加载输入，新进程读取新输入。

日志的 `RulesetVersion` 使用实际整体指纹，历史数据库列名 `FaqVersion` 使用整个已采纳来源集合哈希。`NEEDS_RULE_AUDIT` 继续保留，没有把版本绑定提升为规则认证。权威状态、初始回放状态、恢复命令及同步选择的 origin/preview 均检查当前输入；即使篡改后的初始、最终哈希相同，回放也不能通过。

SQL 009 只增加实际身份字段，不回填旧开发局。正常命令、拒绝命令、事件、权威快照、玩家快照和提示均记录同一输入；恢复检查所有历史行及命令/状态 payload。已有 match 的身份或版本不匹配时，journal 事务回滚，不能更新 tick、增加命令或覆盖旧身份。新等待房间可在首条命令前从已记录身份和持久化席位恢复；缺失身份或损坏权威 payload 不走这个路径。
