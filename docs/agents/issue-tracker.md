# Issue tracker: GitHub

Issues and specs live in GitHub Issues for DDDHL0704/riftbound. Use gh inside this repository.

- Read: gh issue view <number> --json number,title,body,labels,comments.
- List: gh issue list --state open --json number,title,body,labels,comments.
- Create or comment using --body-file with a temporary UTF-8 file; preserve actual newlines.
- Label only after triage direction; each triaged issue has exactly one category (bug/enhancement) and one configured state.
- Every issue or comment produced during triage starts with: > *This was generated by AI during triage.*
- For a requested ticket, read all discussion and verify the behavior before writing an agent brief.
- Create missing configured labels during confirmed setup.
- Close or reject only with maintainer direction.

## Pull requests as a triage surface

PRs as a request surface: no.

An explicitly named PR is read directly; ordinary discovery includes issues.

## Publishing and fetching

When a skill says publish to the issue tracker, create a GitHub issue after the applicable triage direction. When it says fetch a ticket, read the issue and comments.
