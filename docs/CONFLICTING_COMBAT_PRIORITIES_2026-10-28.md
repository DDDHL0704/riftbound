# Combat damage with conflicting assignment requirements

[CN core rules](https://cdn.playloltcg.com/lol/2026/10/2026-10-10/a21ead876c6b44d6abe386b6ae54ea28.pdf) 467.2.c.6–9 require the allocating player to follow applicable restrictions when possible. When one target has both Bulwark and Back Row, the player may satisfy either requirement for that target; with multiple such targets the requirements are chosen independently. A target cannot be placed between ordinary targets when neither requirement can be satisfied. Rule 467.2.c.10 preserves the existing treatment of a unit that cannot take damage.

The existing command carries source, target and damage amounts; it does not carry an explicit target order or the player's choice of requirement. The server therefore checks whether at least one selection of priorities is compatible with the totals, lethal thresholds, partial allocations and excess damage. It uses a bounded search over the three priority levels, not an exponential search over all combinations of mixed targets. The original source-pool, damage-immunity, lethal and excess checks remain in force. A valid deterministic interpretation is reconstructed for event role and assignment-index metadata; it is not evidence that the player submitted an order.

The prompt retains `targetPriority` as the default suggested ordering and adds `targetPriorityOptions` to expose all legal priority interpretations. Its guidance and the Godot damage panel identify a target with both requirements as eligible for either first or last. The server remains authoritative for command validation, and older prompts without the new options remain readable by the client.

The original failing command rows, the initial invalid-fixture recovery failure, corrected fixture evidence and subsequent tests are retained in local QA receipts. Controlled session tests verify both players, the damage events, per-command cold restoration and duplicate handling, and replay from the recorded initial state. This change does not admit or implement VEN·004's separate player-and-location-specific “ignore Bulwark” ability. It does not establish an ordinary opening, PostgreSQL, L2, L3 or complete backend acceptance.
