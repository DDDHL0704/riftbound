# Beginning-phase rune-count triggers

The reviewed CN sources identify VEN·005 and VEN·006 as beginning-phase abilities conditioned on their controller having fewer controlled runes than an opponent. The source snapshot is `data/official/upstream/2026-10-28/reviewed-rune-source-universe/card-catalog.zh-CN.json`; its exact API identifiers do not authorize inferred print aliases. The condition is checked when the trigger is captured, before scoring and channeling, in accordance with CN 383.2.a.1. Exhausted runes in play count; rune decks and resource pools do not.

Each printed or actually attached copy creates an independent ability. VEN·005 gives its original unit +1 Might for the turn; VEN·006 gives +2 Might and Ganking. The captured ability still resolves if the comparison later changes or the copied text is detached. If the original unit leaves play or its token ceases, the ability cannot modify a later incarnation. Source IDs are hidden in public snapshots and resolution events when a new incarnation is private. The public context rejects unknown fields; an absent token source is accepted in component recovery only with a validated captured frame and a known token factory. Replay of original commands remains necessary to authenticate that historical frame.

Focused local tests exercise both printings, equal and greater rune counts, actual responses, expiration, Ganking movement, copied equipment text, both Image/Ephemeral orders, source departure, private views, cold restoration and controlled-history replay. Initial missing-trigger, unexpected-public-field, ceased-Image and private-event failures remain retained in the local QA receipts. Joint regression also covers existing beginning-draw/recycle, attachment, source identity, Empower, Mighty transitions and recovery guards.

These tests use controlled positions. The reviewed prints remain outside `CardBehaviorRegistry`, so this does not certify normal deck play, ordinary opening history, a complete card, PostgreSQL, L2, L3 or full-backend acceptance. The shared CHANNEL rune-replacement mechanism is a separate dependency owned by the resource line.
