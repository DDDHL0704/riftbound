# 艾翁／草丛与战场替换重审（2026-10-09）

## 权威与旧缺陷

依据已缓存的中国区官方核心规则、QA 和卡牌目录；没有重新同步全站。

- 204.3.a / 383.3.e.2：艾翁的可选横置费用在触发确认时支付，随后开放响应；不是征服后自动横置或结算时才付款。
- 438.1–438.1.a：替换创建指示物并继承状态。既有技能中的“此处”和对象引用仍指向同一个战场。
- 438.4–438.6：原牌置于放逐区域，但不是放逐行动；被替换的指示物消失。
- 438.7：换回继承当前状态；草丛替换草丛后仍能沿关系找到最初的战场牌。
- 官方 QA：换回希拉娜修道院不会补触发它的征服效果；烈娜塔单位技能获得分数不属于在草丛得分，不能触发换回。

旧实现把草丛追加为第三处战场，原战场仍留场，并用标签拼接原牌引用；宣战时提供“使用原战场”选项，实际上没有进行官方意义的换回。此前绿色测试中包含这些错误预期。

## 本批实现

`CoreRuleEngine.BattlefieldReplacement.cs` 集中处理替换、原牌关联、真实战场得分触发、换回与恢复校验。

- 场上的 `ObjectId` 是连续的战场游戏物体身份，替换不更改它或其代次。单位、装备、待命、待处理技能、战场任务与已得分标记继续引用这个位置。
- 原始实体牌使用独立的放逐区域库存 ID 保存；`ReplacedBattlefieldCard` / `ReplacedAtBattlefieldId` 记录双向关联。换回时移除该库存项，将原牌面和拥有者恢复到连续战场物体上。草丛指示物的拥有者为创建者，控制权与状态继承当前战场。
- 草丛再次被替换时不会增加场上战场、重复放逐原牌或丢失原牌关系；换回后不会保留草丛工厂身份或光环。
- 艾翁征服与据守均使用上批共用费用收据、确认与响应流程，包括异画、放弃、来源离场和无法支付横置费。
- 草丛的可选换回接入同一确认顺序，使用无资源费用的 `TRIGGER_OPTIONAL_CONFIRMATION`；确认后响应，结算时再复核场上草丛和原牌。
- 换回触发只从真正的战场得分事件捕获；胜利后不弹出新选择；不会把普通技能加分、恢复原牌或替换本身当成征服/据守/打出事件。
- 原生提示区分“横置传奇”“保留草丛”“确认换回原战场”，明确双方响应后再结算。战场卡面继续从后端当前 CardNo 渲染。

删除旧自动查找活跃艾翁并立即创建的路径、`BRUSH_USE_REPLACED_BATTLEFIELD` 宣战选项/校验/提示，以及未使用的旧审计辅助代码。历史开发对局不做兼容迁移。

## 验证

本批新增 **24** 项；定向新规则、费用回归及原生会话 **43/43**；另一次包含旧草丛/艾翁用例的定向检查 **40/40**。四条生产原生按钮命令均已交给真实 MatchSession，恢复校验与动作/事件回放哈希一致。批次 `check` **9093/9093**，测试 74.76 秒、含构建总计 79.58 秒；原生构建零警告、零错误。批次结果见 [validation.json](evidence/battlefield-replacement-2026-10-09/validation.json)。

覆盖双方控制与拥有者不同、据守/自然征服、标准/异画、同一战场二次替换、技能先后顺序、原牌放逐与返回、当前状态和位置保留、此处/异处光环、来源失效、错误玩家、伪造恢复关联、胜利边界及两条官方 QA。

旧战斗用例删除过时的草丛宣战选项后，改为真正完成双方伤害分配再断言战斗关闭；不再依赖该选项导致的旧自动战斗路径。原有“宣战时可选原战场”的正向断言改成拒绝断言，由真实得分后的正向流程替代。

原生验证为无头生产控件及命令验证，不代表视觉验收、两窗口完整自然对战或 Windows 实机验收。未重启服务或用户当前对局。完整长局矩阵由 CI 执行。

## 下一批尚未闭合

- 其他可选据守技能与带目标技能的确认时机：CHANNEL_OPTIONAL、BOON、MOVE_BASE、RETURN_PERMANENT 等仍有旧结算选择路径。
- 其他传奇征服效果仍有直接执行入口；维克托／莉莉娅等指示物的基地或受控战场选择仍未补齐。
- 本批的替换机制针对战场；不能外推为所有卡牌类型替换、全部基础规则或全部 QA 已通过。
