# Optional rune channel on playing a powerful unit

The exact reviewed CN printings are OGN·249/298 (official catalog ID 31491) and FND-249/298 (ID 31576). The [current CN catalog endpoint](https://lol-api.playloltcg.com/xcx/card/searchCardCraftWeb) gives both the optional “exhaust to channel” wording. The [OGN physical face](https://cdn.playloltcg.com/lol/card/20250731/fac82805f12244f380068c3ea51a6aa1.png) has that same cost wording. The [FND physical face](https://cdn.playloltcg.com/lol/card/20250810/a50fb0ff3d904fd9a691293c53ba96d0.png) uses different wording: it says to exhaust and then play an exhausted rune. A specific FND erratum or rule establishing which of these two texts takes precedence has not been verified. FND confirmation-stage exhaustion is therefore a runtime candidate based on the current catalog, not a settled ruling. Both faces are optional.

[CN core rules](https://cdn.playloltcg.com/lol/2026/10/2026-10-10/a21ead876c6b44d6abe386b6ae54ea28.pdf) 204.1.c, 204.3, and 383.3.a–b support choosing and paying a base cost at confirmation for the OGN wording; 350.2 allows tokens to be played, and 303.1–2 require game actions to execute one at a time. The October regional judge FAQ addresses this legend and a rune-call replacement on the chain, but does not itself settle the FND wording discrepancy.

The engine records an independent trigger for each qualifying unit entry using its actual effective Might and the legend's attached rule-text instance. A player can decline; accepting pays the exhaustion cost before an opponent can respond. The subsequent call uses the shared rune-call replacement path. Each last-breath token is placed before its entry is captured, consistent with the existing spell-token producer. Public views expose only the permitted card and confirmation fields, while recovery checks the captured source, unit generation, event and entry frame. Replay of the original command history is still required to authenticate historical state.

The original P79 assertions are retained; their setup now orders and confirms the optional legend trigger. Focused tests cover choice, multiple triggers, unit entry, actual responses and privacy, replacement and short rune supply, forged recovery fields, cold restore, duplicate commands, and replay. Their receipts are scoped to controlled positions. They do not establish ordinary opening or full-card conformance, real PostgreSQL execution, L2, L3, or complete backend acceptance.
