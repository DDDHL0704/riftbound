# 项目治理与验收约定

2026-10-12 起生效。当前产品是服务端裁定的 Godot .NET 原生 macOS / Windows 对战平台，React DevUi 用于调试和协议验证；历史调度和写锁不再具有执行权威。

用户已确认 GitHub Issues、默认 triage 标签、优先验证反馈与证据治理、后台固定提交 CI、明确文档白名单及本轮清理范围。本轮不创建替代 Goal；这些确认不等于新目标授权。

## 来源与信任

规则改动记录官方 URL、取得时间、SHA-256、发布/生效日期、语言地区和印次/条款/QA身份。当前适用与未来已发布版本分开，中国区和国际资料不无说明混合。离线快照不能自动称为官网最新。

9月及更早实现、旧coverage、旧green和Java oracle默认未重新认证。日期不是错误或删除理由。10月来源明确的限定结论保留准确范围，不能扩大为整卡通过。

注册表示有处理映射，索引表示资料已列入，运行结果表示指定输入的检查完成；它们与语义认证分别记录。Implemented / RepresentativeRulePass 由registry推导，不能充当审核结论。

## 范围与完成条件

全量清单保存在 docs/evidence/rules-reaudit-2026-10-11/all-card-ledger.json 和 all-rule-ledger.json，决策另存 review-decisions.json。重建索引不得丢弃原始决策或批量把状态改成PASS。

限定结论须有来源版本/适用性、精确范围、共享实现及全部相关调用、正反例、真正执行的测试身份/输入版本/输出，以及恢复、回放和必要原生证据；未覆盖消费者明确保留。

完整回归通过不能证明全部语义。全量认证还要求全部适用卡牌、条款、FAQ/QA、勘误和非游戏条目逐项处置，解决来源缺口，完成完整回归、原生、双客户端、网络、打包和Windows验收。未来或区外条目保留明确处置，不能让它们消失。

当前全部ledger仍未完整审查；31条scoped review形状不同，不能直接算完成率。轻量治理检查只检查索引、引用和声明一致性，不提升语义认证。

## 验证节奏

| 范围 | 开发反馈 | 收尾 |
|---|---|---|
| 小范围规则 | focus加相邻域 | 连贯批次一次check |
| 跨规则/集成 | focus/check | 固定提交CI full |
| 已确认纯治理文档 | 引用/格式/治理 | 轻量CI，明确规则/打包未执行 |
| 数据、fixture、脚本、构建配置、未知或不确定diff | 对应检查 | 默认full |
| 最终候选 | 全部所需范围 | full与原生/双客户端/Windows闭合 |

普通规则与最长对局尽早启动；权重只影响顺序，不控制纳入或复用通过。保留所有方法、Theory行、110双向配对、原种子及胜利/回放断言。

固定提交CI与下一批开发可并行。本地并行验证使用独立固定checkout，不修改其源文件或bin。方案、来源研究和远端CI可自然并行。

不同提交的CI互不取消，同一SHA的重复任务可取消重复；不能按scope完成顺序把旧提交当最新。保存提交/输入/程序集哈希、来源版本、profile、环境、run ID、TRX哈希及方法/用例/配对身份。旧full仅写上一完整基线；轻量提交不声称执行了full。

CI保留稳定检查名称与明确范围判定。未知范围走full，判定失败不能让重任务静默跳过。使用精确路径白名单，不用docs或Markdown通配；文档提交不取消代码验收。

## Git与清理

每个连贯批次包含实现、必要测试和有来源的限定结论，再检查并提交推送。长期小manifest记录范围、提交、结果和TRX哈希；大日志按用途保留。避免补状态再次触发完整回归。

保留官方快照、ledger、原始trace、必要fixture和有效工具。删除须有用途/调用证据及测试保留说明；长文件、重复字节或无入站链接不足以证明无用。

五份旧累计调度记录仅留固定Git历史入口，不再追加活跃写锁或目标。本轮清单和原始哈希见 [cleanup.json](evidence/project-governance-2026-10-12/cleanup.json)。
