# 图库合并的 JSON 类型冲突修复

图库合并工具原来使用 Python 字典相等判断同一身份的来源是否一致。嵌套字段从 `true` 变为 `1`、从 `false` 变为 `0` 时，该比较仍返回相等；整数 `1` 和浮点表示 `1.0` 也被归为相等。因此不同内容可以被最后一个视图覆盖，并在单条合成示例中得到零差额结果。这是工具输入边界的可复现缺陷，**不是已观察到官网实际发生这些变化，也不是英文八条差额的原因认定**。

修复限于 `scripts/audit/gallery_coverage.py` 和对应测试：按保留 JSON 值及字段的规范序列化内容比较，忽略对象成员顺序；布尔与数值、不同数值表示、缺失字段与 null 不再混同。非有限数值不能序列化为标准 JSON，直接拒绝。不新增地区、产品或印次对应推断。

验证先执行反例：同一视图内和两个视图之间的三组内容变化共六例，以及三个非有限数值，修复前均未按要求拒绝；原红测日志完整保留。修复后全部 **87 个工具测试方法通过**，原十个图库窗口诊断方法及其实现文件逐字节未改。对象成员重排和完全相同的重复记录仍按原行为接受并显式计数。

另从既有、哈希已核验的原始采集归档离线读取分页、整表和 SSR 三个视图。修复前后的全部 1408 条输出记录与完整比较收据一致，逐字段也等于既有基线；报告总数 1416、实际身份 1408、差额 8 保持不变。此验证复用了 10-23 已取得的原响应，没有重新请求官网，也没有把缺失身份改成已知。

原 17 个 Drawings 门禁、卡牌/规则清单和所有未解决来源缺口不变。未修改公共 manifest、台账、Engine、SQL、客户端或测试调度；未执行游戏 check/full、数据库或原生验收。脚本变更由主窗口整合后按固定提交完成必要的完整验证，当前工具绿测不代表全量审计完成。
