# 规则开发反馈速度改进

此次提速部分只修改测试调度工具、开发约定和 CI 入口，没有改变游戏规则、删除测试断言或减少完整对局矩阵。

旧流程每次批次都等全量，最新基线机械重打批次 **9004/9004** 通过，用时 **13 分 2 秒**。该基线中，FullGameEndToEndTests 的 135 个用例累计约 770 秒，单个预组交叉对局用例约 282 秒；数千项基础规则和恢复测试并非主要瓶颈。

新增 `scripts/test-rules.py` 提供规则域、批次检查和完整并行三档。CI 保留完整测试，改用相同的受校验分片入口；本机和 CI 的测试范围不靠历史通过记录决定。

| 本机验证 | 实际结果 | 含构建与发现的总时间 |
|---|---|---|
| `focus recast` | 125 项通过 | 12.61 秒 |
| `check` | 8871 项通过，包括两条完整对局冒烟 | 78.97 秒 |
| 并行完整对照（4 进程） | 9004 项通过，测试名称与数量完全一致 | 314.87 秒（5 分 15 秒） |

不同档位覆盖范围不同，不能把快速档的耗时当成完整测试的加速倍数。完整对照已通过 `--expect-trx` 核对，9004 项测试名称与数量的多重集合与旧全量完全相同。全量耗时约减少 **60%**；新入口的总时间还包含增量构建与发现，旧基线为测试输出的持续时间。这是本机单次实测，不是统计性能保证。

结果、分片 TRX 哈希和工具源码哈希见 [benchmark.json](evidence/rules-test-speed-2026-10-09/benchmark.json)。

工具的防漏分片、动态 Theory 发现、空筛选、缺失用例和跳过拒绝等 6 项 Python 测试通过。`git diff --check` 通过。运行证据在 `var/qa/rules-test-speed-2026-10-09/`；它是本次本机测量，不代表不同机器的固定性能承诺。

使用说明见 [工作流](RULE_TEST_WORKFLOW.md)。本次没有触发远端 CI；GitHub 上实际耗时和 Windows 上工具执行尚未验证。网络、原生界面和平台交付的验收边界没有改变。
