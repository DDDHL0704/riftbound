# 回合开始、据守与延迟产费重审

状态：本批实现与验证记录；全部基础规则、全部卡牌及 QA 的重审仍未完成。不可据此标记 READY。

## 官方依据

沿用本日重新下载的中国区 13 份官方资料，来源、日期、SHA-256 见 [语料清单](evidence/rules-reaudit-2026-10-08/official-corpus.json)。核心规则 CN 315.2.b.2 / 383.4.d 规定据守发生在开始阶段的得分计算步骤；防守获胜本身不是据守。CN 383.4.d.2.c 规定得分被防止或替换时仍触发据守效果。CN 312.2.c / 383 允许对已确认的触发技能进行响应。CN 316.3–4 要求先清空资源池，再处理主阶段开始效果；CN 390–392 的已触发/延迟技能不随来源离场而消失。

苍蓝雕纹魔像采用官网勘误后的“在你的下一个主阶段开始时获得任意符能”；UNL 裁判 QA 明确其增幅包括单位及战场的据守效果。所有功能同源异画按官方身份组匹配，不能只匹配一个卡号。

## 这次改动

- 删除战斗胜负处理中的整段立即据守结算，以及失去调用入口的旧据守处理函数。保留实际战斗胜利、伤害分配和战场交接。
- 开始流程保存当前位置，依次处理备战、开始步骤、据守计分、召出、抽牌及进入主阶段。出现结算链、触发排序、卡牌选择或支付时暂停；响应/选择完成后继续，不重新得分、召出或抽牌。
- 据守技能记录触发时的控制者、来源卡牌身份、来源世代与真实战场。普通抽牌等独立技能在来源离场后仍能结算；需要来源仍在场的自身操作、横置费用继续重新校验。
- 苍蓝的延迟产费直接进入普通符文池，发生在主阶段清空资源池之后。删除在支付时兑现、要求来源仍在原战场的旧入口和提示分支。一般历史支付/恢复元数据尚未全部清理，不作为本批通过依据。
- 可选召出、回收废牌、传奇横置等需要玩家选择；能量枢纽有明确支付/放弃窗口。符能不足、越权选择及重复支付均拒绝且不修改状态。可选召出不向选择窗口泄露符文牌堆顶部对象。
- 移除不存在的首回合一律跳过据守限制；是否得分仍取决于实际控制和具体战场规则。宏伟广场检查条件并留出技能响应窗口。
- 修正开始阶段闭环有优先权却不能打出反应牌的权限错误。原生界面显示“回合开始 · 响应窗口／效果选择／效果支付”，窗口完成之前不显示普通行动指引。
- 炼金男爵的金币增益改为使用时检查当前传奇控制与比分距离，不能靠金币残留标记永久生效。

## 验证与旧测试处置

`OfficialHoldSequenceTests` 直接验证开始阶段、真实场地、来源离场、不同控制者、异画、双方响应、反应出牌预览/提交、可选效果、不足/越权/重复支付、恢复以及操作日志重放。`OfficialResourceAbilityRulesTests` 补当前比分、控制者与可见性对金币的影响。

旧测试中的“防守获胜即据守”预期改为负例，保留其防守牌面、反应、伤害分配或 API 提交流程。终局传输安全测试改用投降产生真实终局，保留所有拒绝、隐私及不变性校验。整局驱动现在完成开始阶段的响应/选择后才继续下一步；排序命令使用完整规范字段，保持实际提交与重放一致。宏伟广场及皮城学院的整局测试经过真正的回合切换来触发。

只检查已经删除函数名/源码字符串的旧据守测试已移除；苍蓝的旧支付专用账本测试被新行为测试替代。详见 [变更记录](evidence/hold-sequence-2026-10-08/replaced-test-contracts.json)。这些替换不等于所有被旧测试声称覆盖的卡牌分支已重新验收。

原生 `HoldSequenceInteractionProof.tscn` 使用服务端真实快照验证响应、选择和支付三个阶段标题，并在 1280×800、1440×900、1920×1080 检查布局。已生成 macOS 窗口截图；这是快照渲染验证，不是两个玩家现场完整对局，也不是 Windows 实机验收。运行服务、旧局和安装包未被本批替换。
