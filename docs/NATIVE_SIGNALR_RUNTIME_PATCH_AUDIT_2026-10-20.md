本批修复原生客户端的 SignalR.Common 受影响依赖及服务端实际共享运行时下限，关联 [问题73](https://github.com/DDDHL0704/riftbound/issues/73)。范围为跨平台软件依赖；它不构成第七个游戏来源变化，也不改变 CN/zh-CN、核心生效2026-10-16的全量官方审计目标。来源、精确包版本、执行输入和开放项见 [manifest](evidence/native-signalr-runtime-patch-2026-10-20/source-manifest.json)。Goal active / NOT READY。

## 补丁与来源

实际旧 Mac、Windows 产物均含 Common8.0.0。[Microsoft 公告 GHSA-334f-vvp4-7g6p](https://github.com/dotnet/aspnetcore/security/advisories/GHSA-334f-vvp4-7g6p) 于10-13发布、10-15更新，列明 Common8.0.0–8.0.31及10.0.0–10.0.12的受影响范围，分别由8.0.32及10.0.13修复；10-15修订删除了此前误列的 Core 包。公告涉及有状态重连消息缓冲阻塞和资源保留。旧版本落入范围是已确认事实，不据此声称发生过攻击。

只修改四份构建输入：Godot客户端和原生网络助手的 SignalR.Client8.0.0→8.0.32，API 的 Redis适配包10.0.9→10.0.13及 RuntimeFrameworkVersion10.0.13，仓库 NuGetAuditMode明确为all。原生net8项目原来的实际审计模式为direct；[NuGet官方说明](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages) 和真实旧包负例共同说明，仅保留旧配置不能保证传递 Common 被审计。新的all策略下原8.0.0路径实际因NU1903拒绝恢复，未屏蔽审计或降级警告。当前两项目恢复/发布读取到 Client、Core、Common及Protocols.Json8.0.32。

单独更新 Redis NuGet包不保证框架依赖 API 使用已修复的共享框架，因此声明[最低运行时版本](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props#runtimeframeworkversion)。当前 API 的 runtimeconfig 对 Microsoft.NETCore.App 和 Microsoft.AspNetCore.App 均要求10.0.13；实际旧默认主机在进入托管应用及数据库之前以150拒绝启动，原输出保留。此配置要求部署环境具备相应或可适用的后续补丁版本。
