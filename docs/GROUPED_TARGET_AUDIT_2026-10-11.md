# 分组目标与结算子集审计（2026-10-11）

## 权威与范围

- 官方中国区规则缓存 `var/official/2026-10-08/01.txt`：355.11.a 要求确认时整组合法；355.11.b 要求结算时不再整体合法的原目标由控制者选择合法子集；355.13 的任意数量包括零。359.3.e.2–8 的单个目标失效及对象代次规则继续先执行。
- 355.11.b 直接以妖异狐火举例：四名战力 1 的目标，经响应变为 1、1、2、2，施法者可以保留两名 2，也可以保留两名 1 和一名 2。不能新增原来未选择的目标；原目标一起移至另一处战场仍可合法。
- 官方卡库 `data/official/card-catalog.zh-CN.json`：妖异狐火 `OGN·256/298` 要求同一处战场、任意数量、总战力不高于 4。力量之缚 `SFD·151/221` 是让两名友方单位本回合 +1 的反应牌，用于真实响应回归。

## 实现

- `AnyNumberOfTargets` 与 `TargetsShareBattlefield` 描述目标组规则；本批为妖异狐火注册。共享目标数、同处／合计战力校验用于初始预览、提交及结算。
- 任意数量的上限按当前合法候选数计算，不再把战力上限当作数量上限。零战力目标可以超过四名。prompt 保留逐目标合法候选，组合交给服务端费用预览／提交校验，不再生成任意数量目标的全排列。
- 结算先屏蔽区域、保护、对象代次等原因失效的单个目标。剩余组合不合法时，用共享决策检查点暂停原结算；施法者逐个移除原目标，整组合法后才能确认。所有子集均可通过有限次移除到达，包含空集；不会自动选择子集或新增目标。
- 原决策检查点在全部选择完成前不提交原结算。继续消费原命令，保留恢复校验、请求身份、重复意图和事件回放。原目标位置保留空位以免改变效果语义。
- Godot 阶段标题、按钮及选择摘要区分“法术结算重选目标”和“摧毁替换”；移除后继续选择，最终确认后继续原结算。

- `GroupedTargetNativeTests`：合计超限和分散位置两条路径各调用生产 ActionBar 三次；每步检查权限、恢复、重复意图和完整命令／事件回放。两个子集场景的变化状态直接种入，真实响应另有独立测试。
